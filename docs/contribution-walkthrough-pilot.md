# One-learner contribution walkthrough: blank protocol

This is a plan and reusable blank record, not a completed session. Keep completed
records private. Do not combine these outcomes with the earlier foundation-lab
pilots: the activity, version, and assessment differ.

Current material version: `contribution-workflow-r1-2026-11-01`.

## Prepare and run

1. Invite one consenting Python/basic-circuit learner; record prior Qiskit, Git,
   Rust, test-writing, and historical-fix exposure. Agree note retention and get
   separate permission for any recording, quotes, or public work links.
2. Freeze a commit or local material version. Run both release commands in the
   [case guide](contribution-case.md). Record environment failures separately.
3. Allow a setup check and a provisional 60–90-minute walkthrough. Record actual
   times and incomplete work; this is not a promised completion time.
4. Start with policy questions, predictions, and a saved initial test sketch
   before opening the case guide or reference tests. Then reproduce, navigate
   source, refine the test, and prepare a review packet. Record reference exposure.
5. Select a follow-up scenario using the instructor guide and check prior exposure.
   The guide is public; a question is not fresh merely because it is in that guide.
   Record the first answer before giving hints and the prompted answer separately.
   No submissions, maintainer messages, or CLA signing.

## Observation record — copy into a private location

- Pseudonymous participant ID; session date; material commit/version:
- Prior skills and solution exposure; note-taking consent/retention agreement:
- Python/OS/Qiskit versions; setup duration; active troubleshooting vs downloads:
- Official policy revision/date read; learner's task-specific checklist:
- Expected behavior prediction, before seeing output:
- Old release attempted / observed behavior / commands / elapsed time:
- Fixed release attempted / observed behavior / commands / elapsed time:
- Source/test map, including which layer is Python vs Rust:
- Initial test sketch; revised regression and rationale; references/help used:
- Nonzero control and stated limits:
- Follow-up scenario, prior exposure, initial answer, each prompt, final answer:
- Practice review packet prepared / incomplete / not attempted:
- Most important blocker and proposed material change:

For each activity label evidence **observed** or **self-reported**, and help
**documentation-only**, **hint**, **facilitator**, **reference**, or **AI/peer**.
Do not call a copied regression independent design. Use **not observed** rather
than inferring understanding from a green check. Learners may stop without penalty.
Count each help episode, including any explanation-check prompt. Preserve raw
records unchanged; put later corrections or interpretations in a dated addendum.

## Decision after the session

If the learner can explain a reproduction/test packet, retain the sequence and
identify remaining gaps. If setup, language prerequisites, or facilitator answers
dominate, narrow the case or revise prerequisites before expanding. Report a
blocked or incomplete attempt honestly. One session establishes neither learning
gains nor readiness to contribute Rust code. Seek technical feedback without
assuming anyone has agreed to further review. Re-estimate grant deliverables and
effort before changing the proposal; more practice stages are not automatically
additional funded labs.
